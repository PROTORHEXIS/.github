# PROTORHEXIS Security Policy

[简体中文](../../SECURITY.md) · **English** · [Français](SECURITY.fr.md) · [Español](SECURITY.es.md) · [Русский](SECURITY.ru.md)

PROTORHEXIS takes security concerns, responsible disclosure and participants' privacy seriously. This is a **default organization-level guide**. Each repository defines its own supported versions, maintenance commitments and product-specific response process.

## Scope

- Do not assume that every project has been released, is supported in production or offers a vulnerability bounty.
- First check the affected repository for a local `SECURITY.md`, supported versions and an actual confidential reporting option. Repository-specific policies take precedence.
- This default guide does not promise fixed response times, bounties, remediation deadlines or disclosure dates.

## How to report privately

1. Prefer the **Report a vulnerability** option on the affected repository's Security page **if that feature is actually enabled there**.
2. If no confirmed confidential reporting channel exists, **do not publish** exploit details, credentials, private data or sensitive examples in public Issues, PRs, Discussions or organization descriptions.
3. If the repository allows ordinary Issues, you may post a **non-sensitive request** asking maintainers to provide an appropriate confidential channel. Share technical details only after a private channel has been confirmed.
4. Provide only the information necessary to investigate the problem, redact personal data and tokens, and do not perform unauthorized scans or access other parties' systems or information.

## Handling expectations

Maintainers will determine an appropriate response based on repository maintenance status and risk assessment. A reply or fix by any specific deadline is **not guaranteed**. Coordinate disclosure to avoid increasing exposure before the issue has been verified and mitigated.
