# PROTORHEXIS — Общие правила сотрудничества организации (проект)

[简体中文 / English](../COLLABORATION_BASELINE.md) · [Français](COLLABORATION_BASELINE.fr.md) · [Español](COLLABORATION_BASELINE.es.md) · **Русский**

> Статус: `PROPOSED` · Репозиторий: публичный `.github` организации · Ответственные: владелец организации или назначенные сопровождающие.
>
> Документ описывает область действия и условия включения общих шаблонов. Он не является утверждённой спецификацией продукта, архитектурным решением, изменением прав доступа или доказательством выполненного аудита безопасности.

## Цель и состав

Обеспечить единый и проверяемый порядок сообщения о проблемах, обсуждения предложений, подачи PR и координации раскрытия уязвимостей, сохранив за каждым проектом ответственность за свой код, правила, CI и выпуск.

| Файл | Назначение | Ограничение |
| --- | --- | --- |
| [CONTRIBUTING.md](CONTRIBUTING.ru.md) | Сотрудничество, конфиденциальность, доказательства | Не обещает принимать внешние изменения |
| [PULL_REQUEST_TEMPLATE.md](../../PULL_REQUEST_TEMPLATE.md) | Область, разрешения, риски, проверки, HOLD | Не заменяет ревью или обязательные проверки |
| [bug_report.yml](../../.github/ISSUE_TEMPLATE/bug_report.yml) | Сообщение об ошибке | Без чувствительных деталей в публичном доступе |

| [config.yml](../../.github/ISSUE_TEMPLATE/config.yml) | Сохраняет свободную форму Issues | Может быть переопределён в проекте |

## Наследование и включение

Поддерживаемые служебные файлы из **публичного репозитория `.github`** на его основной ветке могут использоваться в **публичных и закрытых** репозиториях организации, где нет собственного файла соответствующего типа. Локальный файл имеет приоритет. Шаблоны не устанавливают права доступа, защиту веток или обязательное ревью.

Пока файлы находятся в отдельной ветке и **Draft PR**, они являются только предложением: **не действуют для остальных репозиториев**. Наследование может начаться после слияния в основную ветку. Файл `AGENTS.md` в `.github` автоматически не наследуется; агенты должны читать действующие инструкции и решения своего проекта.

## Полномочия и значение доказательств

1. Утверждённые спецификации и решения, код, миграции, тесты и факты, привязанные к коммитам, остаются в ведении соответствующих репозиториев.
2. Разделять `target` (цель), `implementation` (реализацию) и `gap` (расхождение). Цель не доказывает её выполнения.
3. Разделять `PROPOSED / ACCEPTED / IMPLEMENTED / STATIC_VERIFIED / LOCAL_PASS / REMOTE_CI_PASS / UNVERIFIED / BLOCKED / HOLD`. Невыполненная проверка — `NOT RUN`, а не `PASS`.
4. Локальные проверки с указанной средой и доказательствами не равны успешному GitHub Actions Check. Проблемы CI, квот и оплаты фиксируются отдельно.
5. Содержимое закрытых репозиториев, неопубликованные исследования, конфигурации прав и журналы безопасности не становятся открытыми из-за размещения шаблонов в публичном репозитории.

## Условия перед включением

- [ ] Проверить все публичные тексты на конфиденциальные и неразрешённые к публикации сведения.
- [ ] Подтвердить реальный конфиденциальный канал для сообщений об уязвимостях; не выдумывать адреса и включённые функции.
- [ ] Проверить наследование и приоритет локальных шаблонов в публичном и закрытом репозитории; без проверки отметить `NOT VERIFIED`.
- [ ] Проверить реальное отображение двух форм Issue в GitHub, обязательные поля и предупреждения.
- [ ] Подтвердить сохранение проектных инструкций, ревью, CI, точного коммита, HOLD и правил выпуска.
- [ ] Получить явное разрешение владельца на действие шаблонов во всех подходящих репозиториях до перевода PR в готовый к слиянию статус, затем соблюдать политику ревью.
